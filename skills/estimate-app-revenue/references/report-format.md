# 报告模板

```text
## 结论

- 分析对象：App 名称、App ID、开发者、artistId
- 目标期间：YYYY-MM；全球/国家；iOS、Mac 或全部
- App 月消费者支出：USD X-Y（gross，证据等级）
- Studio 月消费者支出：USD X-Y（gross，证据等级）
- Studio 税前到账：USD X-Y（proceeds，使用的扣除假设）
- CNY 参考值：CNY X-Y（汇率来源与日期）
- 利润：无法判断 / 有直接成本证据时的区间

一句话解释区间由哪些定量证据形成，以及最大的未覆盖项是什么。

## 官方事实

| 项目 | 结果 | 来源与观察日期 |
| --- | --- | --- |
| 开发者与作品数量 | ... | Apple ... |
| 平台构成 | ... | Apple ... |
| 头部 App 商业化 | ... | App Store ... |

## 定量证据

| 对象 | 指标与数值 | 月份/窗口 | 地域/平台 | 口径 | 来源 |
| --- | --- | --- | --- | --- | --- |
| ... | ... | ... | ... | gross/未知 | 链接，观察日期 |

## 推导

1. 明确哪些区间相加、求交或仅用于旁证。
2. 写出 gross 区间，不对开放区间取中点。
3. 写出 proceeds 的扣除率来源和上下界计算。
4. 汇率换算保留原币结果并注明日期。

## 收入集中度

- 头部 App：...
- 长尾：...
- 无法覆盖：Mac / 广告 / Web / 企业授权 / 其他国家或商店

## 不确定性与反证

- 来源冲突、时间错位、付费墙、地区差异、下架产品。
- 哪条新证据最可能缩窄当前区间。

## 证据等级

- 等级：A / B / C / D / 证据不足
- 原因：用一到两句话对应等级标准。
```

## 表述要求

- 先给区间和口径，再给过程。
- 使用“估算”“第三方口径”“未计入”，不使用“确定赚了”。
- 核心结论附近直接放链接，不把证据全部堆到文末。
- 数值精度与证据一致：粗粒度来源使用千美元或万元级区间。
- 若无法得到 Studio 总额，仍可报告目标 App，但必须明确二者不可互换。
