# 流程验证与对比证据

在用户要求完整流程回归、多个分支、长页检查或效果对比时读取。单个局部页面修正按其影响范围抽取，不强制建立庞大截图工程。

## 覆盖计划

先从路由和状态模型列清主流程、各分支、汇合后的公共页及最终出口。已有流程比尚未齐全的稿件更完整时保留后续路径，不能把“没有稿”当作删除依据。

每个独立渲染状态有稳定 key；同页顶部、底部、空选、选中、难度档位、进行中与完成态可以分别记行。复用同一张稿件时注明状态差异。按流程顺序排列分支，不靠文件名排序推断路由。

记录以下信息即可，不要求特定文件格式：

| 字段 | 用途 |
| --- | --- |
| key、页面、分组/分支、状态 | 稳定映射路由与截图，回头可定位和补拍 |
| reference | 稿件节点或已有基线；无稿时明确留空 |
| 设备与系统 | 真实目的地、逻辑尺寸、截图像素尺寸/倍率，避免混淆点与像素 |
| 截图路径及来源 | 原生运行 / Preview / 静态稿及对应代码版本；fixture、预设滚动位置或冻结动画需注明 |
| 问题、调整、复验结果 | 区分发现、修复和已验证，不把“优化”当作通过状态 |
| 交互与边界 | 记录真实动作和结果；缺少能力、未执行项单列 |

## 运行检查

使用项目允许且当前可用的工具选择精确目的地，不依赖历史工具名和默认设备。若 Preview 不能固定指定设备，停止该项并说明；已有原生运行能力可继续使用，证据名称仍为原生运行。

采样前确认当前安装与启动入口对应本轮代码，避免把旧包或历史图片当作新验证。坐标交互应根据当前页面层级定位，转场后刷新，不沿用静态截图或上一页的点击位置。

每种布局验证关键位置与状态：

- 固定页面：导航、标题、关键说明、输入和 CTA 均在有效区域；图片不挤压控件，点击区域不随视觉压缩而缩小。
- 长列表：顶部和底部均采样，确认固定页头没有移动；最后一项在可见滚动视口内并位于 CTA 操作区上方。AX 中存在该元素只证明可访问树含有它，不证明屏幕上可见。
- 覆盖底栏：核对最终滚动位置下末项的可见部分与点击位置。仅增加一个任意 bottom padding 不构成通过，底部安全区也不能重复计入。
- 状态/流程：空状态的禁用、选择/保存、返回保留、分支汇合和出口；动画在完成前的禁用与完成后的推进，返回/离页后任务取消或重入行为。
- 动态信息：换一组真实输入核对摘要、时间或关联选项；Figma 数值不是业务来源。
- 输入页：按任务范围实际唤起软件键盘，核对焦点、输入框、提交与收键盘操作。硬件键盘输入成功不证明软件键盘出现后仍无遮挡；涉及中日韩组合输入时另核对候选及提交行为，未执行则保留边界。

如确需几何记录，统一坐标系。有效视口以真实窗口与滚动区域的交集为基础，再排除固定页头、TabBar、CTA 等实际遮挡；依据当前容器测量，不复制其他页面的固定偏移。对于应完整显示的末项，确认整个目标 frame 进入该视口，再结合截图和实际点击确认。AX 中存在或 `isHittable` 为真，均不能单独证明完整可见。

拖动起终点应落在该有效视口内，并锚定当前目标 ScrollView 的局部坐标；页面或姿态变化后刷新层级。手势无效或可见性断言失败时，对照原图、滚动位置和实际命中结果，先区分生产布局、宿主约束与测试坐标问题，再决定修改位置。

共享组件修改后回查所有受影响布局类别，不只看 SE。至少包含指定参考设备；是否增加更大设备、Dynamic Type 或旋转取决于任务和支持范围，未测不做结论。

## 隔离数据与临时入口

优先复用项目现有 Mock、Preview fixtures 和可注入依赖，用生产 View 渲染。完整流程状态采样可能需要临时宿主，但不能为截图建立另一套页面，也不能改变生产流程、持久化结构或跳过实际业务门禁后宣称通过。

宿主应对齐正式入口中影响布局的祖先容器与环境，包括导航、安全区、固定底栏、可读区域约束及语言。新增 `sheet` / `fullScreenCover` 时重新核对其内部根节点，外层菜单具备某项约束不代表弹层内部自动继承。宿主导致的错误宽高应先修正宿主并重采；旧图保留原版本和排除原因，不据此修改生产布局或宣称正式页面通过。

保存正式代码与本轮临时代码的边界，尤其不要在结束时用改动前的备份覆盖已经修好的实现。预设选中项、滚动锚点、笔画和冻结百分比是截图手段，应显示来源标签。真实系统权限、购买、传感器及手势只有实际执行后才算验证；工具未暴露能力时不绕过限制。

采样结束后清理临时入口、注入、跟踪日志及环境变量引用，检查正式源码；必要时对恢复正式入口后的代码重新构建安装运行。关闭本轮创建且不再使用的设备会话。

## 三列比较页面

用户要求对比网页时，先复用项目已有报告和生成器；没有时以最小静态页面满足需求。无需为普通单页适配引入报告框架。

默认布局为从上到下按页面/状态排列，从左到右为 **效果图 → 参考设备运行图 → 紧凑设备运行图**，用户另有顺序则遵循用户。明确列名与尺寸，保留图片原始比例；不能把不同高度的手机图强行拉成相同尺寸。长稿提供原图滚动或放大入口。

每行附 key、页面状态、问题/调整和验证状态；截图使用 fixture 时标注。没有设计稿或某台设备尚未采集时直接写明缺失，不生成空白占位图片，也不拿其他设备的截图代替。

检查图片路径存在、可解码及实际尺寸，确保完整覆盖清单；截图像素尺寸可能包含 2x/3x 倍率，不能仅因它不等于逻辑尺寸就判错。网页预留图片宽高/比例以避免加载后跳转错位，确保本地图片链接和搜索/跳转等实际提供的控件可用。代码或状态修正后重拍受影响截图，避免报告引用旧结果。

## 最终状态

分别报告构建、逻辑测试、Preview、原生渲染、真实交互与未测事项。完整渲染截图集不等于全部真实交互；逻辑测试也不能证明文字或末项可见。按实际证据收敛结论，保留复验方法和逐页修正清单。
