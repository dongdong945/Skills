# SwiftUI 小屏适配

把现有页面修到小屏上关键信息完整、操作可达、流程连续，同时复验参考设备。保持一套自适应实现；根据任务选择只读检查或实际修改，不因使用本技能扩大页面、设备或业务范围。

## 先确认基线

1. 阅读项目约束及目标模块，确认入口、分支、公共后续页、返回/恢复、页面状态和数据来源。把“页面”拆为需要验证的状态：空选、选中、长页顶部/底部、动画前后等。未提供新稿的后续页沿用已有流程。
2. 确认参考稿尺寸、指定设备、系统版本和可用工具。iPhone 12 的逻辑尺寸通常为 390×844，SE3 为 375×667；实际目的地与截图尺寸仍需核对。用户指定的设备优先，不能以默认 Preview 设备替代，也不自动增加第三台设备。
3. 先读当前组件，再查项目指定的成熟实现。STAR 项目可参考 STAR112 同职责页面，但保留当前项目的状态、依赖与业务契约；读取 [STAR 判断与布局模式](references/star-layout-patterns.md) 核对 700pt 等约定的边界。
4. 发现当前环境实际暴露的构建、Preview、设备交互能力。项目限定 Xcode MCP 时，使用对应能力；全局约定或用户已允许截图回退且 MCP 无法提供有效截图时，改用 Xcode / Device Hub 原生图形界面完成采集，无需重复确认，记录失败情况、实际采集方式及尺寸。截图回退不扩大其他操作权限，不用 XcodeBuildMCP、shell 或其他工具绕过；其余能力缺失记录验证缺口，继续能完成的工作。

范围包含 Duo 或动态窗口时，先确认实际可读区域与尺寸变化；普通竖屏 iPhone 的紧凑高度分类不代表折叠姿态。涉及动态窗口改造时结合可用的 `app-resizability`；本技能负责其中短空间下的内容与操作可达性。

## 判断哪里需要适配

从截图、实际布局和交互判断，不把设备型号或“编译成功”当成适配结果。必要时记录窗口、页头、滚动视口、末项与 CTA 的位置。

| 观察 | 优先判断 |
| --- | --- |
| 主视觉挤压说明、输入或操作 | 空白和插图的高度预算是否过大；图片可见绘制内容是否与资源 frame 一致 |
| 滚动后标题消失，内容穿过导航 | 谁应固定、谁应滚动；导航背景和裁切是否属于正确容器 |
| 末项在按钮后面或点不到 | 父级是否实际预留底栏空间，而非仅声明了 inset |
| 长标题被开关或其他控件挤碎 | 实际译文、控件占宽和间距是否超过横排预算 |
| 权限或失败提示出现后无法返回 | 正文覆盖层是否越过自己的容器并拦截固定导航 |
| 同一页面的子控件适配分支不同 | 是否误用扣掉 CTA、键盘或局部容器后的高度重新分类 |
| 修改后仅 SE 正常 | 共享布局是否改变参考设备正文起点、背景构图或安全区 |

高度分类在稳定的页面/Flow 根容器计算并向下传递，测量点位于页面局部底栏和内容压缩之前。不要按型号分支，也不要读取屏幕全局高度代替容器可用高度。宽度用实际约束连续适配；短高度不能自动代表窄宽。键盘、转场、Sheet 或旋转导致的高度变化，应先明确页面应否重新布局，再决定是否保留首次分类。

## 修改顺序与布局选择

先保护标题、关键数据、输入、状态、返回和 CTA。压缩非关键留白，再等比调整装饰或示例主视觉；保留既有字体层级和触控区域。内容仍超预算时调整滚动结构，不对整页做全局缩放，也不静默删掉说明、最后选项或后续页面。

按页面职责选择结构，而非给所有 ScrollView 套同一补丁：

- **问卷/选择/配置页**：标题和说明按设计固定，选项或正文获得剩余空间并滚动；检查滚动视口裁切，避免内容绘到页头。长篇汇总、报告等完整文档可以整页滚动。
- **普通固定底栏**：优先复用项目的 safe-area 组件。自定义 Flow 中若空间没有实际预留，可改为正文和底栏同级分配高度；同时复验常规设备。不要为此替换所有正常 inset。
- **明确要求渐变覆盖的底栏**：保留覆盖语义，内容末尾为完整操作区、渐变和必要的 safeBottom 预留滚动空间。确认 inset 所有者，避免重复补偿；仅背景延伸到安全区，按钮仍可点击。
- **滚动穿过导航**：用现有 customNavigation/config 管理底色和安全区，核对子页是否自带标题条。不要再叠一层导航或重复增加顶部高度。
- **固定网格/分页/主视觉页**：先预算行列、图片和间距。已有水平分页且固定内容可容纳时，不机械地为每页再增加纵向滚动；动态长内容超预算则重新安排滚动。
- **文字与控件同排**：按实际译文和原生控件占宽预算，保留完整换行与触控区域；空间不足时让文字或控件独立成行。用目标语言中的长文案复查，不硬编码英文换行，也不只靠高度分类解决横向不足。
- **正文内权限/错误覆盖层**：将覆盖与命中范围限制在相应正文，保留固定返回和退出操作；实际进入该分支，再返回核对草稿或进度。产品明确要求的全屏模态按自己的关闭契约处理。

布局修改不应改写数据和完成条件。对时间、任务、星期等动态信息使用另一组输入复查，不能为了贴稿而写死。动画页需验证全部信息能在推进前看到，以及取消、重入和完成门禁；不复制其他页面的固定时长。

## 运行复验与交付

完成单页或共享容器修改后，在指定小屏与参考设备上验证对应状态；共享组件变化覆盖其受影响页面。完整流程、分支或三列对比要求出现时，读取 [流程验证与对比证据](references/flow-verification.md)。

- 长页既看顶部，也看底部；固定页头位置应稳定。结合截图与辅助功能层级确认末项可见，再实际选择末项、点击 CTA 进入下一页。AX frame 可能超出裁切视口，不能单凭两个全局 frame 推断可见或可点击。
- 复查空选禁用、选中/保存、返回保留状态、分支汇合及自动推进。仅执行与本次影响相关的交互和业务检查；普通布局改动不需要无关测试。
- 静态/预设状态截图只证明渲染；初始滚动锚点不等于真实滑动，预置笔画不等于手绘，冻结进度不证明实际计时。Preview、原生运行、逻辑检查和真实交互分别记录。
- 若要临时注入数据或截图入口，核对宿主与正式入口的布局容器及环境，详见 [隔离数据与临时入口](references/flow-verification.md#隔离数据与临时入口)。先保留修改后的正式代码；结束时只清理本轮注入，复核正式入口并按需重新构建运行。关闭本轮创建且不再使用的交互会话。

交付逐页列出问题、修改或无需修改的理由，并标明设备、状态、证据与未覆盖项。只读任务给出判断和建议；修改任务遵循当前项目的提交约定，不由技能自行授权 push、合并或发布。
