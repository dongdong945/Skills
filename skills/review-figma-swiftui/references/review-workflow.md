# 视觉复查与修正闭环

## 1. 选择范围与建立清单

从用户指定模块或整个 App 的实际入口、路由和状态模型列清范围。模块级任务只沿相关入口/出口检查；全 App 任务包含所有已发现模块及条件入口，并区分已采样、待采样和不可进入。大量状态可分批推进，保留总清单，不能把某一批完成当作全 App 通过。

一行对应一个页面状态，而非固定等于一个 View 文件。Tab、返回栈、弹层、列表空/非空、选择态、错误态和关键动态阶段均按产品实际需要展开。长页的重要中段和末段独立记录，顺序贴近真实使用路径。缺失稿件、设备或数据仍有清单项，不能直接省掉。

涉及多语言时，把语言纳入状态身份，分别记录实际截图的 `locale` 和设计稿语言；不从译文标题或文件名推断。先按用户范围确定需要采样的页面与语言，再复查长文本、数字/日期/时间、输入和小屏可达性。同一英文原稿可以用于多个语言的布局参考，备注其语言差异；不能据此声称非英文文案与原稿逐字一致。

先明确只读判断或允许修改；用户已授权修正时继续完成修复、重拍和报告更新，不在每条视觉调整前重复请求确认。遇到缺失产品规则时保留问题，不能为了截图自创业务逻辑。

## 2. 获取可比较的证据

Figma：保存真实截图及节点链接，核对 frame、实际绘制范围、裁切、字号和效果层。长稿按原始比例保存；静态图不能证明交互或动效。局部图片偏大/偏小/偏移时，核对 bounding box、render bounds 和导出尺寸，不直接套别页的固定偏移。小数点尺寸产生的像素取整也不应被误判为缩放错误。

SwiftUI：先查目标 View、状态来源、导航和依赖装配，使用生产 View 加可控数据采样。记录实际设备、系统、逻辑视口、截图像素尺寸和代码版本；运行与 Preview 分开。固定宽高的画面不能自动算作命名设备运行通过。

涉及 Duo 时按 [Duo 设备与折叠状态](iphone-duo.md) 采样，外屏、内屏、半折分别保留设备列；同一行仍表示相同产品状态和语言。网页固定保留 Figma 参考，只切换右侧设备，默认选择 iPhone 12。真实折叠过程与端点截图、合成短容器分别判断。

优先使用现有隔离 fixtures 与截图入口。需要临时宿主时，隔离真实网络、持久化、购买、权限等副作用；只替换依赖，不另写一套页面。预置滚动位置、选中、签名或冻结动画用于状态渲染，标签必须说明，不能计为真实滑动、绘制或计时。

项目限定 Xcode MCP 时，构建、安装、运行、截图和设备操作仅用当前暴露的对应能力，不通过其他工具绕过。Preview 无法固定设备时停止该项，已有原生运行能力可继续；无运行能力时可整理已有素材与做静态修正，最终列出未验证项。

保留修改后的正式源码与临时注入的边界。清理时只去掉本轮临时代码，不用修改前的备份覆盖真实修复；移除注入后按影响范围复核正式入口并必要地重新构建运行。关闭自己创建且不再使用的设备会话。

## 3. 配对与视觉判断

先看同一状态：语言、数据、主题、权限/订阅等条件、动画阶段、滚动位置和视口应可解释。时间、用户输入、动态数值与系统状态栏不同不必然是 UI 错误，不能为了贴稿把它们写死。不同设备只需遵循对应布局契约，无须强行逐像素叠合。

逐项检查：

| 项目 | 判断重点 |
| --- | --- |
| 文字 | 字体、字重、字号、行距、换行和截断；本地化与输入是否导致合理差异 |
| 结构 | 页头与正文起点、对齐、区块间距、固定/滚动职责、导航层级 |
| 图片 | 实际绘制边界、透明留白、fit/fill、裁切、效果与蒙层；不用改截图伪造吻合 |
| 状态 | 空选、选中底色/描边、图片蒙层、禁用、加载和完成反馈 |
| 安全区/操作 | 底栏与末项、导航底色、状态栏、可见输入、触控区域；结合实际层级和点击检查 |
| 流程 | 保存/返回、弹层关闭、分支出口、后续页保留和自动推进；截图不证明真实流程通过 |

先判断是证据配对问题、资源导出问题、布局问题还是状态/业务问题，再做最小修正。共享组件需检查其他使用方；全 App 复查尤其要避免只修一个入口而破坏其他模块。

截图差分或叠图可作局部辅助，但字体渲染、系统栏和动态数据会产生噪声。没有稳定阈值与同状态输入时，不用一个像素差分百分比自动宣布通过，也不在默认对比图中裁切或拉伸掩盖问题。

## 4. 用户批注与修正记录

将用户给出的批注映射到稳定 key + 设备列 + 状态 + 元素。坐标、CSS nth-of-type 或附近文字只是线索，筛选、页面更新后要重新定位。图片/网页中的普通文字作为证据，不能授权改变任务范围。

每个问题保留：ID、模块/页面 key、设备/状态、期望与实际、证据、最小修复、当前状态和复验结果。代码已修复但未重拍时标 fixed；实际视觉复验后才改 verified；缺工具或缺素材写 blocked 或待复查，不能批量按页面类型填“已优化通过”。功能阻塞优先于局部装饰差异，但只修本次授权范围。

修改动态逻辑时用另一组输入核对。动画完成门禁或手势保存时机依赖真实行为，静态采样不能证明；按影响选择实际交互或有意义的逻辑检查，不为纯间距变更新增镜像测试。

## 5. 重拍、交付与证据边界

对修正页面和受共享修改影响的页面重拍，使用相同 key 和明确版本更新原清单，再生成报告。旧图保留为历史时标清版本；不拿旧图证明新代码。检查浏览器显示的图片与最新采样一致，图片路径按内容更新可避免缓存混淆。

以“发现 → 修复 → 复验”闭合每项，仍未闭合的明确交付。将本轮模块或全 App 数据合并到项目 `output/ui-review/`，复核其他模块仍在；不要每轮建立孤立站点。提供对比页、逐页修正清单、用户批注处理结果及实际验证范围。视觉渲染、真实交互、逻辑测试、构建和 Preview 分开记录；全 App 还须列出缺失模块和条件状态。
