# 检索 Obsidian 知识

从 `/Users/dongdong/Documents/Obsidian Vault` 获取与当前任务相关的个人知识。只读使用 Vault；本 Skill 不新增、修改或删除笔记。

## 工作流程

1. 确认 Vault 和 `system/Home.md` 可读。不可用时说明本次未使用知识库并继续任务，不要虚构历史结论。
2. 先读 `system/Home.md` 了解索引，再从用户目标提取项目名、功能名、错误文本、App ID、技术名词及同义词。
3. 使用 `rg` 搜索 Markdown 文件名、frontmatter、标题和正文，并排除 `.git/` 与 `.obsidian/`。先查精确标识，再扩大到同义词。
4. 按以下顺序选择结果：
   - `wiki/` 中已验证、可复用的方法和定义。
   - `outputs/` 中与当前对象直接相关的评估、问答和候选结论。
   - `raw/` 中的原始材料；只在需要核对一手上下文时读取。
5. 包含 `system/Home.md` 在内最多读取 5 篇笔记。优先选择范围匹配、状态明确、更新时间较新且能直接影响当前决策的内容；不要把整个 Vault 注入上下文。
6. 提取可执行结论、适用范围、证据边界、停止条件和未决事项。区分笔记原文、当前代码或资料确认的事实，以及基于两者作出的推断。
7. 用当前仓库、运行结果或官方文档复核易变化事实。Obsidian 中的版本、价格、排名、API 能力和外部状态只能作为线索，不能替代实时证据。
8. 若笔记之间冲突，保留冲突并优先采用证据更强、范围更匹配、更新时间更近的结论；无法消解时明确告知用户。

## 输出约束

- 只把真正影响任务的知识带入回答，不复述无关笔记。
- 当 Obsidian 内容实质影响结论时，在回答中列出使用过的 Vault 相对路径或 Obsidian 链接，例如 `wiki/playbooks/App-Opportunity-Validation.md`。
- 不把候选结论表述为已验证知识，不把历史判断表述为当前事实。
- 不因检索到相似笔记而跳过当前任务必要的代码检查、测试或资料核对。
