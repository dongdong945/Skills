# Git 提交流程

## 概述

用于检查当前改动、生成符合约定的中文 commit message，并完成 `git commit`。

默认采用最低成本的直接执行方式，无需深度推理，不做与当前提交无关的额外延伸。

## 执行步骤

1. 执行 `git status`，确认当前仓库、分支、提交授权、改动及未解决冲突；遵循用户和项目的分支约定。
2. 阅读工作区与暂存区 diff，明确本任务路径及已有暂存内容的归属。同文件混合改动需按片段判断，不能用整文件暂存或提交夹带其他片段。保留无关改动和他人的暂存状态，仅提交本任务；不因存在可安全隔离的无关改动自动停工。
3. 阅读 diff，判定唯一前缀：`feat`、`fix`、`refactor`、`docs` 或 `chore`。
4. 按本 skill 的提交规范生成提交信息；标题单行，body 默认使用三段式结构。
5. 提交前核对最终待提交 diff。仅当整个暂存区都属于本任务时，使用临时 message file 执行 `git commit -F <message-file>`；否则先采用能保留用户暂存状态的安全隔离方式。无法保证同文件片段或已有暂存状态不受影响时，再询问具体归属或处理方式。
6. 提交后执行 `git branch --show-current` 与 `git log --oneline -1` 记录结果。
7. 报告实际分支与本地提交结果；是否需要额外确认取决于授权、项目约定及具体冲突，不仅依据 `main` 或 `master` 分支名。提交授权不自动包含 push、合并或发布。

未解决冲突必须先处理再提交。若解决本任务冲突已获授权，且双方意图及文件归属明确，继续完成最小冲突修复、自审和必要验证；涉及无关工作、归属不明或需要新的产品决策时保留现场，只询问具体阻塞点。不要用 reset、checkout 或批量暂存清理用户现场。

## 提交规范

### Prefix

根据 diff 的主导意图选择唯一前缀。跨类别时选主导类别，优先级：`feat > fix > refactor > chore > docs`。

| Prefix | 场景 | Emoji |
| --- | --- | --- |
| `feat` | 新功能、新 UI 组件、新文件实现功能 | ✨ |
| `fix` | Bug 修复、崩溃修复、错误处理修正 | 🐛 |
| `refactor` | 代码重构、架构调整，不改变外部行为 | ♻️ |
| `docs` | 仅文档变更 | 📝 |
| `chore` | 构建配置、依赖更新、CI、工具链维护 | 🔧 |

### 标题

标题格式严格为：

```text
<prefix>: <emoji> <中文动词短语>
```

标题必须单行。动词短语必须中文，英文仅限技术标识符、文件名、类名、方法名、框架名、平台名。必须以动词开头，例如：添加/修复/移除/重构/更新/优化/实现/替换/调整/配置/迁移/支持/处理/完善/拆分/合并/封装/简化/提取/补充/降低/前置/兜底。必须具体描述本次变更内容，禁止“更新代码”“修复 bug”“调整逻辑”等模糊表述。

### Body

除非用户明确要求只生成单行提交信息，否则提交信息必须包含标题和三段式 body。

```text
<prefix>: <emoji> <中文动词短语>

<段落一标题>：<说明本次变更的背景、问题或动机。>

<段落二标题>：<说明复现路径、使用路径、影响范围或验证方式。>

<段落三标题>：<说明实现思路、修复思路、处理方式或风险控制。>
```

不同前缀使用以下段落标题：

| Prefix | 段落一 | 段落二 | 段落三 |
| --- | --- | --- | --- |
| `fix` | 问题描述 | 复现路径 | 修复思路 |
| `feat` | 需求背景 | 使用路径 | 实现思路 |
| `refactor` | 调整背景 | 影响范围 | 重构思路 |
| `chore` | 变更原因 | 影响范围 | 处理方式 |
| `docs` | 文档背景 | 阅读范围 | 更新内容 |

每段独立成段，段落之间空一行。内容必须基于 diff、测试结果、日志或用户提供的信息；不确定的信息不要编造，使用“未覆盖”“未复现”“未验证”等明确表述。禁止添加 Markdown 列表、脚注、测试报告长日志或无关说明。

## 快速检查

- 无改动时直接停止，不生成 commit。
- 有未解决冲突时不提交；在已授权范围内可明确解决的继续处理，否则保留现场并说明具体阻塞。
- 无关改动保持原状，不混入本次提交；已有暂存内容也逐项核对归属，无法安全隔离时再询问。禁止使用裸 `git add -A`。
- 提交标题必须是单行，且动词短语必须是中文。
- 提交 body 必须遵循三段式结构，除非用户明确要求只生成单行提交信息。
- 英文只允许出现在技术标识符里。
- 输出里包含提交信息和实际分支；仅在存在具体授权或分支约定问题时说明，不按分支名自动追加警告。
- prefix、emoji、标题和 body 结构必须遵循本 skill 的提交规范。
- 优先根据当前 diff 直接生成并提交，无需深度推理或额外延伸。
